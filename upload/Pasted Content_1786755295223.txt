SCHOLARIO-OS — PRINCIPAL EXAMINATION MODULE
NEXT ITERATION: SMART EXAMINATION TEMPLATES + AUTOMATIC EXAM GENERATOR

IMPORTANT:
This is NOT just another UI polish iteration.

The current Create Examination screen looks better, but the fundamental workflow is still wrong.

Right now the system shows templates such as:

• Unit Test
• Periodic Assessment
• Half-Yearly Examination
• Annual Examination
• Practical Examination
• Pre-Board Examination
• Oral / Viva Examination
• Custom Examination

BUT after selecting a template, the Principal still has to manually configure almost everything.

That defeats the purpose of templates.

The objective of this iteration is to turn these into REAL SMART EXAMINATION TEMPLATES.

The correct mental model is:

SELECT TEMPLATE
→ PROVIDE THE MINIMUM REQUIRED INPUT
→ SYSTEM AUTOMATICALLY BUILDS THE EXAM
→ PRINCIPAL REVIEWS
→ CREATE EXAMINATION

The Principal should NOT have to manually construct the entire examination every time.

============================================================
1. CORE PRINCIPLE
============================================================

A template is not merely:

"Unit Test" + prefilled text.

A template is a predefined examination policy.

It should already know:

• what kind of examination it is
• which classes it normally applies to
• which subjects should be included
• default maximum marks
• theory/practical/oral structure
• passing rules
• preferred examination duration
• subject difficulty/priority
• how many shifts are required
• how subjects should be distributed across dates
• scheduling rules
• whether practical/oral components apply
• whether the examination is board-oriented
• default result calculation rules

Therefore:

When the Principal selects a template, the system should AUTOMATICALLY build almost the entire examination.

The Principal should mostly need to choose the examination date/date range.

12. SMART SCHEDULING ENGINE
============================================================

This is one of the most important changes.

When a template is selected and dates are provided:

the system should generate the timetable automatically.

It should consider:

• selected date range
• school working days
• selected classes
• subjects
• subject difficulty
• maximum daily examinations
• morning/afternoon shifts
• examination duration
• practical requirements
• oral requirements
• holidays if available
• existing school timetable conflicts
• existing examination conflicts
• teacher/invigilator availability where possible

Do not simply generate random dates.

The result should look like a professionally planned school examination timetable.
