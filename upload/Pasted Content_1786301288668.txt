SCHOLARIO — TIMETABLE FINAL UX REFINEMENT
IMPORTANT: THIS IS A REFINEMENT PASS, NOT A REDESIGN

The current Timetable module is already in a very good visual state.

DO NOT rebuild the page from scratch.
DO NOT replace the current timetable grid.
DO NOT introduce unnecessary new cards.
DO NOT add extra filters or controls just because they seem technically useful.

I want you to refine the current implementation according to the exact workflow below.

The screenshots/current implementation are the visual reference.

The goal is:

CLEAN VIEW
→ EDIT
→ MAKE CHANGES
→ APPLY CHANGES
→ PUBLISH UPDATE
→ USERS GET NOTIFIED
→ AFFECTED SLOTS SHOW A SMALL CHANGE VISUAL

Keep the existing Scholario visual language:
minimal
premium
white/light
soft borders
subtle shadows
green primary actions
small icons
very little text
smooth micro-interactions
no AI-looking UI
no excessive pills
no giant modals
no unnecessary gradients
no visual clutter.

============================================================

When Principal clicks the "+" inside a timetable cell, the modal currently asks for:

Day

Do NOT show these fields in the normal slot-assignment UI.

============================================================

Room/Lab filtering is actually useful in a school timetable.

============================================================
27. APPLY VS CANCEL
============================================================

The distinction must be absolute.

CANCEL:

discard only unsaved Edit-mode changes.

APPLY CHANGES:

commit the current edit session.

After Apply:

the changes are now saved/pending publication.

Then:

Publish Update

becomes available.

If Principal later enters Edit mode again and makes more changes:

those new changes are UNSAVED.

Cancelling them must NOT undo previously applied/pending changes.

This is critical.
