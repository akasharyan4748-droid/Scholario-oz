     3→ * (Parent Connect / Student Behavior / Student Mentoring).

     6→ *  • runtime-resolved ids only — school by slug, teacher by email, students
     7→ *    by class roster; NO hardcoded cuids;
     8→ *  • idempotent — deletes this school's Teacher Hub rows, then re-creates;
     9→ *  • relative dates (daysAgo/daysAhead) so the demo never goes stale;
    10→ *  • honest data — every conversation message, behavior record, session,
    11→ *    goal and follow-up is a real row the modules will actually read.

    18→const daysAgo = (n: number, h = 10, m = 0): Date => {
    19→  const d = new Date()
    20→  d.setDate(d.getDate() - n)
    21→  d.setHours(h, m, 0, 0)
    22→  return d
    23→}
    24→const daysAhead = (n: number, h = 10, m = 0): Date => daysAgo(-n, h, m)
